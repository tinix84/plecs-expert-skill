## Rule for the manual extractor (#11)

`extract_manual.py` may write into `skills/*/references/` only the factual layer it pulls out of `plecshelp.qch`/`docs.plexim.com` — parameter names, defaults, units, ranges, table structure, RPC/XML signatures, and other data that Circular 33 treats as unprotectable facts — always paired with a source-URL citation so provenance stays auditable, and it must not write Plexim's own explanatory sentences, examples, or narrative prose into the repository even in "extracted, cited" form, since Plexim's own terms of use bar reproduction for anything beyond personal, non-public use; any full-text corpus or search index the tool builds from the manual for its own convenience (e.g. to power fuzzy lookup) should be generated at run time or cached outside the git tree (e.g. `.gitignore`d under a local cache directory), never committed, and any hand-written prose that accompanies the facts in `references/` must be the caveman-style, independently authored text the project already produces per `LICENSE-NOTES.md`, not a paraphrase tight enough to be a derivative of Plexim's wording.

## Open judgement calls for the owner

- Where is the line between an "independently rewritten" explanation and a "close paraphrase" of Plexim's prose? This is a substantive-similarity judgement call that these sources don't resolve mechanically; worth a spot-check by the owner on a few `references/*.md` files.
- Whether the *selection and arrangement* of a table (which parameters to list, in which order/grouping) can itself attract thin copyright protection as a compilation, even though the individual facts don't — Circular 33 flags this possibility without settling it for this specific case.
- Whether to add a `THIRD-PARTY-NOTICES` file (or extend `LICENSE-NOTES.md`) to carry the MIT copyright notices for any code adapted from `PLECS-C-Script-Skill` or `plecs-mcp`, versus inlining the notice at each reused file's top — both satisfy MIT, but pick one convention for consistency.
- Whether "personal use" in Plexim's terms could plausibly cover an individual engineer's private, unpublished reference notes (not this public repo) — relevant if the owner wants a *local-only*, gitignored cache of extracted manual text for their own lookup, separate from what ships in the repo.
- Whether to reach out to Plexim for a documentation-reuse permission, which would change the "prose" row of the decision table if granted.
- Whether to contact the `PLECS-Testauto-Skill` author to request an explicit licence (even a permissive one added retroactively) if anything from that repo is actually wanted.
