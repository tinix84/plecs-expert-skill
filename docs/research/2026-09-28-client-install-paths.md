## Unverified

- **`CODEX_HOME` effect on the skills path specifically** — the Codex docs confirm `CODEX_HOME` changes the Codex profile/config home (default `~/.codex`) but do not explicitly restate that this also relocates `$HOME/.agents/skills`. Do not assume it does without testing.
- **ChatGPT desktop app skill directories** — no ChatGPT-desktop-specific (as opposed to Codex CLI) directory documentation was found separate from `learn.chatgpt.com/docs/build-skills`, which is framed around Codex/CLI usage. Whether the desktop app reads a different local path was not confirmed from a primary source.
- **Gemini CLI SKILL.md frontmatter field list** — the docs describe that the SKILL.md body and folder structure are added to context on activation, but do not publish an explicit enumerated list of recognized frontmatter fields (unlike OpenCode's or Claude Code's explicit lists). Only `name`/`description` are implied by the discovery/trust model description.
- **GitHub Copilot CLI / VS Code environment variables for skill paths** — no env var was found in either doc.
- **Cursor environment variables and installer command** — none documented; discovery is automatic only.
- **agentskills.io's `~/.agents/skills` claim** — CONFIRMED as a shared user-level location by three of the requested primary sources: Codex (`$HOME/.agents/skills`, https://developers.openai.com/codex/skills), Gemini CLI (`~/.agents/skills/` alias, https://geminicli.com/docs/cli/skills/), and GitHub Copilot CLI (`~/.agents/skills`, https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills). Cursor and OpenCode also document reading `~/.agents/skills`/`.agents/skills`, though they were not part of the three clients the ticket asked to check for this specific claim.

## Implications for tools/install.py and README

- A single skill checkout can satisfy **Codex, Gemini CLI, Copilot CLI, VS Code Copilot, Cursor, and OpenCode** simultaneously by installing (or symlinking) into `.agents/skills/<name>` at repo level and `~/.agents/skills/<name>` at user level — all six read that alias per their own docs. This should be the default target for `tools/install.py`.
- **Claude Code and Claude Code plugins** do not read `.agents/skills`; they require `.claude/skills/<name>` (repo) or `~/.claude/skills/<name>` (user), or plugin-based distribution. OpenCode and Cursor and VS Code Copilot *also* read `.claude/skills`/`~/.claude/skills` for compatibility, so installing into both `.agents/skills` and `.claude/skills` covers every filesystem-based client checked here except claude.ai.
- **claude.ai** has no filesystem install path at all — it needs a packaged `.zip` (skill folder at zip root) uploaded manually via Settings > Features. `tools/install.py` cannot automate this end of the chain; at most it can produce the correctly-shaped zip artifact for the user to upload by hand. README should say this explicitly rather than implying one install step covers claude.ai too.
- Frontmatter portability: only `name` and `description` are safe to rely on everywhere. `license`, `compatibility`, `metadata`, and `allowed-tools` are the next-safest optional fields (read by most CLI-based clients and by Claude Code's "outside Claude Code" spec-compliant subset). Fields like `when_to_use`, `argument-hint`, `arguments`, `model`, `effort`, `agent`, `background`, `hooks`, `paths`, `shell`, `disable-model-invocation`, `user-invocable`, `context`, `icon`, `color` are client-specific extensions (Claude Code, VS Code, or Cursor each read a different subset) and should not be treated as required by the skill's own SKILL.md if the goal is cross-client compatibility.
- README should not claim CODEX_HOME relocates skills — that specific behavior is unverified; state only what's confirmed (profile/config home).
